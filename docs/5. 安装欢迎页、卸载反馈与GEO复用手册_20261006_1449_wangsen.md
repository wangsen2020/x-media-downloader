# 安装欢迎页、卸载反馈与 GEO 复用手册

把 X Media Downloader（xdown）这两天做的工作整理成可复用的步骤，同步到 X Blocker（xblocker）和 X Article to PDF（xexport）两个扩展及其子站。

参考实现全部已上线：

| 仓库 | 关键提交 |
| --- | --- |
| x-media-downloader | `1b55352` 1.5.4：安装打开欢迎页、设置卸载反馈 URL |
| xdown-website | `31fbfa9` 欢迎页 + 卸载反馈页 + D1；`0247443` GEO；`6cc78cc` 无需 X Premium 文案 |
| goodexts-website | `1b589ab` 主站 xdown 卡片与介绍同步 |

方案与决策过程见 [4. 安装欢迎页与卸载反馈方案](4.%20安装欢迎页与卸载反馈方案_20261005_0045_wangsen.md)。

## 一、整体思路

- **安装**：扩展首次安装后打开子站的本地化欢迎页 `/welcome`。页面教用户怎么用，配截图，不是首页。这给官网一次曝光。
- **卸载**：`chrome.runtime.setUninstallURL` 指向子站的 `/uninstall` 页。收集卸载原因，顺带推广另外两个扩展。这又是一次曝光。
- **存储与通知**：Cloudflare Pages Functions 写入 D1，同时推送到 Telegram。全部免费额度内。
- **隐私**：URL 只带版本、浏览器语言、安装日期和固定的 utm 参数，不带任何用户标识。数据库不存 IP 和 UA。

## 二、扩展端改动（每个扩展都要做）

不需要新增任何权限。`tabs.create` 和 `setUninstallURL` 都不需要权限。

### 1. 新增 `src/lib/site.js`（纯函数，便于测试）

照抄 xdown 的版本，只改两处：`SITE` 和 `ext` 代号。

```js
export const SITE = 'https://xblocker.goodexts.com';   // xexport 用 https://xexport.goodexts.com

export function siteLocalePrefix(uiLang) { /* zh*→/zh, pt*→/pt-br, es*→/es, 其余 '' */ }

export function welcomeUrl({ uiLang, version }) {
  // /welcome?utm_source=extension&utm_medium=install&v=&hl=
}

export function uninstallUrl({ uiLang, version, installed }) {
  // /uninstall?utm_source=extension&utm_medium=uninstall&ext=<代号>&v=&hl=[&installed=]
}
```

`ext` 代号建议：

| 扩展 | 代号 |
| --- | --- |
| X Media Downloader | `xmd`（已用） |
| X Blocker | `xbl` |
| X Article to PDF | `xap` |

代号会出现在 D1 的 `ext` 列和 Telegram 消息的前缀 `[xbl] 卸载反馈` 里，用来区分是哪个扩展的反馈。API 校验规则是 `^[a-z0-9-]{1,20}$`。

子站的语言前缀必须和子站的 i18n 配置一致（都是 en 无前缀，zh / pt-br / es 有前缀）。扩展支持的其他界面语言（日、韩、阿拉伯等）一律落到英文页。

### 2. `background.js`

```js
import { welcomeUrl, uninstallUrl } from './lib/site.js';

async function setUninstallUrl() {
  try {
    const { installedDate } = await chrome.storage.local.get('installedDate');
    await chrome.runtime.setUninstallURL(uninstallUrl({ ...siteDetails(), installed: installedDate }));
  } catch (e) { console.warn('Uninstall URL failed:', e); }
}
setUninstallUrl();   // worker 每次启动都设置

chrome.runtime.onInstalled.addListener(async ({ reason }) => {
  if (reason === 'install') {
    // 存 installedDate（YYYY-MM-DD），然后打开欢迎页
    await chrome.tabs.create({ url: welcomeUrl(siteDetails()) });
  }
  await setUninstallUrl();   // install 和 update 都重设
});
```

- `siteDetails()` 返回 `{ uiLang: chrome.i18n.getUILanguage(), version: chrome.runtime.getManifest().version }`。
- 如果原来安装后会打开 options 页，把它换成欢迎页，别两个都开。
- `setUninstallURL` 的 URL 上限是 1023 字符，现有参数远低于此。
- 如果扩展不是 ES module 的 service worker（xexport 的 background.js 在根目录，要先确认 manifest 里有没有 `"type": "module"`），就把 site.js 的函数直接内联进 background.js，或者用 `importScripts`。

### 3. 测试、文档、版本

- 测试：参考 `test/site.test.js` 和 `test/site-lifecycle.test.js`。覆盖语言前缀映射、URL 参数、URL 里没有多余字段、install 时只开一次欢迎页、update 时不开。
- `PRIVACY.md`：说明卸载时打开的页面带哪些参数，反馈是用户自愿提交的。
- `README` 与 `CHANGELOG`：各加一条。
- 每次改动都要 bump 版本号。

## 三、子站改动

xblocker-website 和 xexport-website 都是从 xdown-website 克隆的同一套模板（Nuxt 4 SSG、4 种语言）。下面的文件基本可以直接拷贝，再改文案。

### 1. 卸载 / 反馈页 `app/pages/uninstall.vue`

- **两种模式**：
  - 默认是卸载模式，原因列表：用不了 / 有 bug、太复杂、缺功能、不再需要、换了别的产品、隐私顾虑、其他。
  - `?entry=feedback` 是普通反馈模式，选项是报告问题、建议功能、咨询、其他。
- **详情必填**：选"用不了""缺功能""其他"，或者在反馈模式下，详情必填。
- **联系方式（选填）**：WhatsApp、Telegram、微信、邮箱任选一种。
- **允许 X 私信**：复选框，默认不勾选。勾选后才出现 X 用户名输入框。
- **防刷**：只有一个隐藏的 honeypot 字段 `website`。不加验证码，用户已明确不要防刷。
- **提交成功后**：卡片滚动回视口（`scrollIntoView`，配合 `.feedback-card { scroll-margin-top: 88px }`，避开吸顶 header）。
- **推广位**：展示另外两个扩展。xblocker 子站推 xdown 和 xexport；xexport 子站推 xdown 和 xblocker。图片放在 `public/images/promo/`。
- **手机端顺序**：`.feedback-intro` 设 `display: contents`，表单卡片 `order: 1`，推广位 `order: 2`，保证手机上先看到表单。
- 页面设 `noindex`。

### 2. API `functions/api/uninstall-feedback.ts`

直接拷贝，不用改。它会：
- 校验 Content-Type、8 KB 上限和各字段。
- honeypot 有值时直接返回 ok、不入库。
- 写入 D1，并从 `request.cf.country` 取国家。
- 通过 `waitUntil` 推送 Telegram，消息为中文。

注意：Telegram 消息前缀里的兜底值写死了 `'xmd'`（`ext || 'xmd'`）。拷贝到别的站后，把兜底改成对应代号，或者改成 `'?'`。

### 3. 欢迎页 `app/pages/welcome.vue`

- 结构：若干步骤，每步一张截图，用 `images` 数组 `{ src, w, h }` 加上 aspect-ratio 容器防止布局跳动。页面设 `noindex`。
- 第一步固定是"把扩展固定到工具栏"。步骤里的扩展名要用 **Chrome 扩展菜单里实际显示的本地化名称**，也就是 `_locales/*/messages.json` 里的 `extName`，不是英文品牌名。
- 置顶动图：`x-media-downloader/tools/welcome-assets/pin_gif.py <源 gif> <输出 gif> <扩展名>`。它基于 WAExport 的置顶动图，替换扩展名和 tooltip，并保留光标。每种语言各出一张 `pin-<locale>.gif`。
- 其余步骤展示各扩展的核心用法：
  - **xblocker**：按关键词或正则找账号 → 确认 → 批量屏蔽。
  - **xexport**：打开文章 / 推文串 → 导出 PDF、Markdown 或 HTML。
- `SiteHeader` 在 `/welcome` 上隐藏"Add to Chrome"按钮，因为用户已经装了。

### 4. 其他接线

- `nuxt.config.ts`：
  - `nitro.prerender.routes` 加上 `/welcome`、`/uninstall` 及其 zh / pt-br / es 版本。
  - `typescript` 配置把 `functions/` 排除掉。
- `i18n/locales/*.json`：新增 `welcome` 和 `feedback` 两组 key，4 种语言都要有。
- 隐私政策页：4 种语言都加一节"卸载反馈"，说明收集什么、联系方式选填、用于回复。
- `README`：加一节说明反馈数据流。

### 5. 本地联调

```bash
NITRO_PRESET=static pnpm generate
CI=1 npx --cache .npm-cache wrangler@4.147.0 pages dev .output/public --d1=DB=00000000-0000-0000-0000-000000000001 --compatibility-date=2026-10-01 --port=8788 < /dev/null
npx --cache .npm-cache wrangler@4.147.0 d1 execute goodexts-feedback --local --config wrangler.local.toml --file schema.sql
```

- `wrangler.local.toml` 只在本地用，不要提交。
- `CI=1` 和 `< /dev/null` 用来防止 wrangler 卡在交互提示。
- 构建前先关掉占用 `.output/public` 的本地 http 服务，否则会报 EBUSY。

## 四、Cloudflare 配置（复用同一个库）

数据库 `goodexts-feedback` 和表 `uninstall_feedback` 已经建好，三个扩展共用，用 `ext` 列区分。新站不用再建库或建表。

在 xblocker-website 和 xexport-website 两个 Pages 项目里各做一遍：

1. 打开 Settings → Bindings → Add → D1 database，Variable name 填 `DB`，选 `goodexts-feedback`。
2. 在 Variables and secrets 里添加：
   - Text：`TG_CHAT_ID` = `5115045923`
   - Secret：`TG_BOT_TOKEN`
3. 绑定和变量只在**下一次部署**后生效。先配好，再推送代码。

关于操作方式：
- Cloudflare 后台用 bsk 操作（用户浏览器里已登录）。
- **Token 必须由用户本人粘贴**，agent 不能往任何输入框里填 token。做法是 agent 先打开对话框，选好 Secret 并填好变量名，然后用 `bsk request-help --session <id> --target <Value 框> --timeout 15m` 把控制权交给用户。注意 `--timeout` 要带单位，写成 `900` 会立即超时。
- 目前用的仍是聊天里出现过的旧 token。等用户在 @BotFather 用 `/revoke` 换了新 token 之后，三个项目的 `TG_BOT_TOKEN` 都要更新，并各重新部署一次。

上线验证：
1. 在线上提交一条 `LIVE TEST` 反馈。
2. 用 D1 Console 执行 `SELECT * FROM uninstall_feedback` 确认有这一行。
3. 在 web.telegram.org 打开 @goodexts_feedback_2_bot，确认收到消息。
4. 删除测试行：`DELETE FROM uninstall_feedback WHERE detail LIKE 'LIVE TEST%'`。

## 五、GEO 优化（AITDK 审计项）

xdown 首页 GEO 审计原来是 86 分。以下逐项都已修复，两个子站照做：

| 审计警告 | 做法 |
| --- | --- |
| 没有 llms.txt | 新增 `public/llms.txt`（llmstxt.org 格式）：H1 站名、引用块摘要，再列首页、博客、联系、隐私、条款、商店链接、GitHub 链接，全部用绝对 URL，只写英文 |
| 没有 Organization / WebSite schema，没有 sameAs | 首页 JSON-LD 合并成一个 `@graph`：Organization（`@id` 为 `${site.url}/#organization`，sameAs 指向 GitHub 和 goodexts.com）、WebSite、SoftwareApplication（sameAs 指向商店和仓库，带 dateModified）、FAQPage |
| 没有作者和日期标记 | `BlogPost.vue` 的 Article schema 把 author / publisher 设成 Organization GoodExts，带 datePublished / dateModified。不编造个人姓名 |
| 标题层级跳级 | 页脚的 h4 改成 h2，CSS 保持外观不变 |
| 缺少数字 | 加一个"At a glance"事实区（`.facts`，`minmax(190px, 1fr)`）。**数字只能取自扩展 README 写明的事实**，不编用户量、评分或百分比 |
| 没有引用 | 引用 X 服务条款、Chrome Web Store 政策和 MIT 许可证原文链接。不编造引语 |
| 没有作者信号 | 首页加署名"由 GoodExts 开发维护"，链接到 goodexts.com 和 GitHub |
| 只有 Contact，没有 About | 新增 `/about` 页（4 种语言，加进 sitemap，页脚加链接），带 Organization schema |

`site.ts` 里加 `githubUser` / `githubRepo`，不要硬编码扩展版本号，否则每次发版都会过期。

验证：
- 生成后用 node 脚本对每个 JSON-LD 块执行 `JSON.parse`。
- 检查首页 h1–h6 的顺序。
- 确认 `llms.txt` 和 `/about` 在产物里，`/about` 也在 sitemap 里。

## 六、卖点文案（各扩展要单独核实）

xdown 发现的卖点是"X 自带的视频下载只对 Premium 会员开放，本扩展对免费账号也能用"。这句话分别写进了：

- 子站 FAQ 新增一问"下载视频需要开通 X Premium 吗？"（同时进入 FAQPage schema，有利于 GEO）。
- "Why use"一节的导语、事实区"免费且开源"一项、`llms.txt` 的摘要。
- goodexts.com 主站的扩展卡片和首页介绍段落。

**这个卖点不能照搬到另外两个扩展。** 每个扩展要找自己真实的对应卖点，核实后再写，例如：
- **xblocker**：X 原生只能一个一个屏蔽；本扩展按关键词或正则批量找到账号，确认后批量屏蔽。
- **xexport**：X 原生不能把 Articles 或推文串导出成文件。

写法要用具体场景把事说清楚，不要堆关键词（CWS 曾因关键词罗列拒审过）。商店描述要等当前版本过审后再改，改 listing 会触发重新审核。

## 七、主站 goodexts.com 同步

每个扩展有重要的新能力或卖点时，同步更新：
- `i18n/locales/*.json` 的 `ext.<id>`：卡片描述。

## 八、踩过的坑

- **Windows 控制台**：GBK 会把 bsk `evaluate` 里的中文 JS 字符串弄乱，要用 Python subprocess 加 `json.dumps` 转义后再传。
- **locale JSON 格式**：zh / pt-br / es 用的是"数组内对象单行"的紧凑格式，en 是 indent=2 的展开格式。用脚本改的时候做字符串替换，不要 `json.dump` 整个文件重写，否则 diff 会炸。
- **GitHub 推送**：网络时好时坏，SSH 和 HTTPS 都偶尔断。写成重试循环，直到输出里出现 `main -> main`。
- **CWS 控制台**：
  - CDP 脚本必须按 item ID 选 tab。
  - 上传 ZIP 前要断言当前在 Package 页，并且页面上恰好只有一个 file input。
  - "Submit for review"按钮在 Store listing 页上，不在 Package 页。
  - 提交前必须得到用户明确确认。
- **截图打码**：涉及隐私的地方用 8–10px 的像素块轻码。
- **先写方案再动手**：新功能先在 `docs/` 写方案，用户确认后再实现。
