## 一、需求与目标

在保留 `x-media-downloader` 纯本地、零服务端隐私架构的前提下，新增 **Google Drive 云端直传** 能力，覆盖图片、GIF 与视频：

1. **零服务端直传**：复用 Chrome MV3 原生 `chrome.identity` + Google Drive REST API v3，不经过任何第三方中转服务器。
2. **UI 触发入口**：复用时间线/帖子下载按钮的**右键菜单**（`src/content.js` 的 `openQualityMenu`），增加「上传到 Google Drive」选项；单次点击即入队，不阻塞用户在 X 页面继续浏览。
3. **Options 页面慢速队列与进度看板**：大视频拉取与分片上传放在 `options.html#uploads` 标签页从容执行（规避 MV3 Service Worker 30 秒休眠中断），并在 `options` 页面新增**上传任务列表**，实时展示上传进度条、已传字节数、状态及云端打开链接。

## 二、总体架构与模块分工

```text
X 页面 (src/content.js)
  └─ 右键下载按钮 -> openQualityMenu() -> 点击「上传到 Google Drive」
       └─ sendMessage({ type: 'xvd:gdrive-enqueue', ... })
            │
            ▼
Service Worker (src/background.js)
  ├─ 解析媒体 URL 与默认画质 / 文件名（复用现有 resolveMedia + buildFilename）
  ├─ 写入持久化队列（chrome.storage.local: gdriveTasks）
  └─ 若 options#uploads 未打开，打开/激活 options.html#uploads 承接传输；已打开则通知其拉起队列
            │
            ▼
Options 上传工作台 (src/options/options.html#uploads + options.js + src/lib/gdrive.js)
  ├─ 按需 OAuth2 授权（XMDGDrive.ensureToken，绝不在安装/启动时弹窗）
  ├─ 幂等准备目录（X Media Downloader / {@user}）
  ├─ 限流队列调度（并发 = 1~2，慢速稳定上传）
  │    ├─ 图片 / 小视频 (<= 5 MB)：uploadType=multipart 一次直传
  │    └─ 中大视频 (> 5 MB)：uploadType=resumable 分块 PUT + 实时进度回调
  └─ 更新任务列表 UI 与存储状态（已完成展示「在 Drive 中打开」链接）
```

### 为什么上传执行放在 Options 页面而不是 Service Worker？

* **规避 MV3 Service Worker 休眠**：Chrome MV3 Service Worker 在无事件约 30 秒后会被回收；高清视频（几十 MB 到数百 MB）拉取 + 分片上传耗时较长，在后台 Worker 中极易被中断。
* **天然可见的进度与授权上下文**：`options.html#uploads` 拥有完整的 DOM 环境、持久生命周期以及稳定的交互上下文，方便展示实时进度条、暂停/重试/取消操作，且更利于拉起 Google OAuth 授权窗。

## 三、认证授权与 Manifest 权限设计

完全借鉴 `x-article-exporter/gdrive.js` 验证通过的双通道按需授权机制：

### 1. `manifest.json` 变更清单（可选权限，避免已上线扩展升级被禁用）

> **线上升级红线**：本扩展已上线 Chrome Web Store，若直接在 `permissions` / `host_permissions` 中新增权限，老用户更新版本时会触发**权限升级警告并被 Chrome 自动禁用**。因此新增权限必须全部放入**可选权限**：

* **`permissions` / `host_permissions` 保持不变**：不新增任何必选权限，确保老用户静默无感升级。
* **`optional_permissions` 新增**：`["identity"]`
* **`optional_host_permissions` 新增**：`["https://www.googleapis.com/*", "https://video.twimg.com/*", "https://pbs.twimg.com/*"]`（三者随首次「连接 Google Drive」一次性申请；包含 `twimg.com` 域可确保 `options` 页面直接 `fetch` 媒体流与读取 `Content-Length` 响应头时不受 CORS 拦截）。
* **`oauth2` 配置**：
  ```json
  "oauth2": {
    "client_id": "<CHROME_EXTENSION_OAUTH_CLIENT_ID>.apps.googleusercontent.com",
    "scopes": [
      "https://www.googleapis.com/auth/drive.file"
    ]
  }
  ```
* **最小权限原则**：仅使用非敏感 Scope `https://www.googleapis.com/auth/drive.file`，扩展只能访问自己创建的目录与文件，避免触发 Google 敏感/受限权限深度审核。

### 2. 可选权限动态申请与双通道 Token 获取（`src/lib/gdrive.js`）

1. **按需触发与用户手势约束**：
   * 安装、更新、打开 Popup 或普通本地下载绝不申请可选权限或登录。
   * 由于 `chrome.permissions.request()` 必须在扩展页面（如 `options.html#uploads`）的**用户点击手势**中调用：
     * 首次使用时，右键点击「上传到 Google Drive」会将任务写入队列并打开 `options.html#uploads`；
     * 若 `chrome.permissions.contains({ permissions: ['identity'], origins: ['https://www.googleapis.com/*'] })` 为 `false`，队列自动处于等待授权状态，页面顶部展示「连接 Google Drive」按钮；
     * 用户点击该按钮后，依次执行 `chrome.permissions.request(...)` → `ensureToken()` → 自动开始队列上传。一旦授予，后续右键入队即可直接自动上传，无需再次点击。
   * **特性检测**：未授予 `identity` 可选权限前，`chrome.identity` 可能为 `undefined`，`gdrive.js` 需先判断权限状态与 API 可用性。
2. **主通道**：优先 `chrome.identity.getAuthToken({ interactive: false })` 静默读取缓存；无缓存且允许交互时调用 `getAuthToken({ interactive: true })`。
3. **兼容回退**：部分 Chromium 派生浏览器不支持内置 `getAuthToken` 时，自动回退到 `chrome.identity.launchWebAuthFlow`（使用 `WEB_AUTH_CLIENT_ID` 请求 `https://accounts.google.com/o/oauth2/v2/auth`，`response_type=token`，`redirect_uri=chrome.identity.getRedirectURL()`），并在 `chrome.storage.local` 缓存有效期内 Token。
4. **401 自动恢复**：请求封装 `fetchWithAuth()` 遇到 `HTTP 401` 时，自动调用 `removeCachedAuthToken` 并清除本地 Web Token 缓存后重刷一次。
5. **取消与未启用 API 区分**：识别用户主动关闭授权窗（`AUTH_CANCELLED`），以及 GCP 未开启 Drive API 的 `403 accessNotConfigured` 错误并给出引导提示。

## 四、目录结构与分级直传协议

### 1. 幂等目录管理（`ensureFolder`）

* 根目录默认名：`X Media Downloader`（缓存 `folderId` 到 `chrome.storage.local`）。
* 可选按作者建子目录（与本地下载习惯一致，如 `X Media Downloader/@user`）：使用内存 `in-flight Promise` 锁防止并发任务首次创建重复同名目录。
* 若云端目录被用户手动删除导致上传返回 `404`，自动清缓存、重建目录并透明重试一次。

### 2. 分级上传策略（图片 Multipart + 视频 Resumable）

| 媒体类型 / 体积 | 上传接口 | 核心流程 | 进度粒度 |
|---|---|---|---|
| **图片 / 小 GIF / 小视频（≤ 5 MB）** | `POST https://www.googleapis.com/upload/drive/v3/files?uploadType=multipart&fields=id,name,mimeType,webViewLink` | `TextEncoder` 拼接 `multipart/related` 请求体（Part 1 JSON metadata + Part 2 `Uint8Array`） | 阶段进度：拉取中 → 上传中(50%→100%) → 完成 |
| **中大视频（> 5 MB）** | `POST https://www.googleapis.com/upload/drive/v3/files?uploadType=resumable` + 分片 `PUT` | 1. 带 `X-Upload-Content-Type` 与 `X-Upload-Content-Length` 初始化会话，从响应头 `Location` 获取 `uploadSessionUrl` 并**立即持久化**；<br>2. 按固定分片大小（**4 MB**，`256 KB` 整数倍）循环 `PUT` 切片并携带 `Content-Range: bytes start-end/total`；<br>3. 收到 `308 Resume Incomplete` 后读取 `Range` 头更新 `committedOffset` 并**每片落盘**；收到 `200/201` 解析返回文件 `id` 与 `webViewLink` | **精确字节与百分比进度**（支持跨重启/断网断点续传） |

> **拉取优化建议**：若大视频在页面端已拿到直链且体积较大，可通过 `fetch(mediaUrl)` 读取 `arrayBuffer()` / `ReadableStream` 分块切出 4 MB 缓冲直接 `PUT` 到 Drive，减少同时驻留内存的副本数量；并在任务取消时通过 `AbortController` 立即中止拉取与 `PUT` 请求。

### 3. 分片断点持久化与恢复协议（Status Check）

为保证 `background` 重启、`options` 标签页关闭或网络中断后仍能精确断点续传，任务恢复时若已存在 `uploadSessionUrl`：

1. **查询云端已落盘偏移量**：向 `uploadSessionUrl` 发送空请求体 `PUT`，携带 `Content-Length: 0` 与 `Content-Range: bytes */<bytesTotal>`。
2. **按状态码分支处理**：
   * **`308 Resume Incomplete`**：读取响应头 `Range: bytes=0-<lastByte>`，将本地 `committedOffset` 校准为 `lastByte + 1`（若无 `Range` 头则从 `0` 开始），直接跳过已传分片继续 `PUT` 下一片；
   * **`200` / `201`**：说明最后一个分片其实已成功提交，直接解析响应体获得 `id` 与 `webViewLink` 并标记任务 `complete`；
   * **`404` / `410`**：说明上传会话已过期（Drive 会话通常保留约 7 天），清空 `uploadSessionUrl` 与 `committedOffset` 后自动重建会话重传。
3. **取消清理**：用户主动点击「取消」时，向 `uploadSessionUrl` 发送 `DELETE` 释放云端未完成会话。

## 六、任务状态机与存储结构

### 1. 任务状态流转

`awaiting_auth`（初次未授权等待用户点击连接） / `queued` → `fetching`（拉取媒体流） → `uploading`（Multipart 或 Resumable 分片上传） → `complete`  
异常分支：`paused` / `failed` / `cancelled`（均支持从任务列表手动点击 `重试` 回到 `queued`）。

### 2. 队列持久化结构（`chrome.storage.local` key: `gdriveTasks`）

单条任务对象控制在精简元数据（不存储二进制数据，上限保留最近 200 条）：

```json
{
  "id": "gd_1795585000_abc123",
  "tweetId": "1890000000000000000",
  "screenName": "NASA",
  "tweetUrl": "https://x.com/NASA/status/1890000000000000000",
  "mediaKind": "video",
  "mediaUrl": "https://video.twimg.com/...",
  "poster": "https://pbs.twimg.com/...",
  "filename": "NASA_launch_20261125_189000.mp4",
  "mimeType": "video/mp4",
  "quality": "1080p",
  "status": "uploading",
  "chunkSize": 4194304,
  "committedOffset": 12582912,
  "uploadSessionUrl": "https://www.googleapis.com/upload/drive/v3/files?uploadType=resumable&upload_id=...",
  "sessionCreatedAt": 1795585001000,
  "bytesUploaded": 12582912,
  "bytesTotal": 38000000,
  "percent": 33,
  "driveFileId": "",
  "webViewLink": "",
  "error": "",
  "createdAt": 1795585000000,
  "updatedAt": 1795585012000
}
```

### 3. 慢速调度与稳定性约束

* **低并发**：默认 `concurrency = 1`（或最多 2），任务之间间隔 `500–1000 ms`，避免瞬时带宽打满或触发 Google Drive API 429/403 限流。
* **增量节流写盘与关键检查点立即落盘**：普通进度百分比在内存中实时刷新 DOM；但 **`uploadSessionUrl` 初始化成功** 以及 **每个 4 MB 分片收到 Drive `308` 确认后的 `committedOffset`**，必须**立即写入 `chrome.storage.local`**，确保任何时候关闭页面或重启扩展都能精准续传。
* **重启恢复**：若用户在上传途中关闭了 `options` 标签页，下次打开 `options.html#uploads` 时，原处于 `fetching` / `uploading` 的中断任务自动标记为 `paused`（或提示可一键恢复），不丢失记录。

## 八、边界场景与工程避坑清单

1. **流式分片防 OOM（`ReadableStream` / `Blob.slice`）**：
   * 严禁对大视频直接 `await resp.arrayBuffer()` 后再切片（几百 MB 视频极易导致标签页内存暴涨崩溃）。
   * 若响应头含 `Content-Length`，使用 `resp.body.getReader()` 边读边凑满 4 MB 分片即 `PUT` 到 Drive 并释放切片引用；若缺少 `Content-Length`，先读为 `Blob` 再通过 `await blob.slice(start, end).arrayBuffer()` 逐片上传。
2. **长队列下的双 Token 过期自愈**：
   * **OAuth Access Token 过期（1 小时）**：Resumable 每次分片 `PUT` 与 `Status Check` 都必须走 `fetchWithAuth()`，遇到 `401` 刷新 Token 后**保留原 `uploadSessionUrl` 和 `committedOffset` 继续传**，不得重置进度。
   * **媒体直链过期（403/410）**：长队列或隔天恢复时若 X CDN URL 失效，自动通过 `tweetId` 重新调用 `resolveMedia`（含 syndication fallback）刷新直链后再重试拉取。
3. **多图帖与混合媒体帖的拆包粒度**：
   * 右键上传多图帖（`_1`~`_4`）或混合媒体帖（视频 + 多图）时，按**单个媒体文件**拆分为独立任务入队，各自独立显示进度与 Drive 链接，支持单文件失败重试。
4. **云端重复上传检测（防 Drive 同名多份）**：
   * Google Drive 允许同目录存在同名文件。建议维护精简 `gdriveUploaded` 映射（`mediaKey -> { driveFileId, webViewLink, uploadedAt }`），再次上传同一媒体时直接提示「已上传过 · 打开或重新上传」，避免重复占用用户云盘空间。
5. **标签页防误关与断网自恢复**：
   * 当 `options.html#uploads` 有任务处于 `uploading` 时，注册 `beforeunload` 轻提示，防止用户误关页面中断传输；
   * 监听 `online` / `offline` 事件，断网自动 `paused`，恢复联网后自动继续队列；遇到 `storageQuotaExceeded`（云盘空间已满）则暂停队列并给出明确提示。
6. **轻量化设置项**：
   * 在 Settings Tab 补充 Google Drive 目标根目录名（默认 `X Media Downloader`）与「按 `@用户名` 创建子文件夹」开关（默认开启）。
