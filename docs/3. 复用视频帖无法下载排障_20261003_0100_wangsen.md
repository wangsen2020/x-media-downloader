# 复用视频帖无法下载排障（1.2.2）

## 现象

有些帖子的视频能在网页上播放，但点下载失败。X 手机 App 里这类视频本身就没有下载按钮。
例子是 `https://x.com/XxLunaLurex/status/2100527111236907083`。

## 排查过程

1. **第一个假设是错的。** 1.2.1 认为问题出在 `world: "MAIN"` 注入时机，修改后问题依旧。
   教训：先抓真实的数据，再下结论。
2. 用 bsk 的 debug 功能抓 GraphQL 响应，发现视频是从另一条原帖**复用**来的：
   - 视频 media 上带有 `source_status_id_str`，指向原帖；
   - 当前帖的 id 与原帖不同，缓存按 id 查找时找不到这条视频。
3. 同时发现 X 把 `screen_name` 从 `user.legacy` 挪到了 `user.core`。旧代码只读 `legacy`，所以作者名变成了 `unknown`。

## 修复

`src/injected.js`：

- 记录的 key 按顺序取：当前帖 id、`media.source_status_id_str`、`expanded_url` 中的 id。复用视频因此在当前帖和原帖下都能命中。
- 作者名先读 `user.core.screen_name`，读不到再读 `user.legacy.screen_name`。

验收：下载到一个 1280×720、31 分钟的完整 MP4。

## 后续

- 1.2.2 上架时，把"手机 App 不能下载的视频这里能下"写进商店描述和 README，作为卖点放在最前面。
- 1.2.3 新增拉美西语 `es_419`。拉美客户比西班牙本土多，商店的语言标识是 `es-419`。

## 可复用的经验

- X 的 GraphQL 字段会悄悄迁移。读取字段时要兼容新旧两个位置，并为两种结构各写一个测试样本。
- "能播放但下载不了"，先查**缓存的 key 是否对得上**，不要先怀疑注入时机。
