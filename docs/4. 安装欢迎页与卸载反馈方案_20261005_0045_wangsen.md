# 安装欢迎页与卸载反馈方案

状态：**已实施（2026-10-05），两个仓库已本地提交，等 Cloudflare 配置好后推送上线**。实施记录见第 11 节。

涉及两个仓库：
- `x-media-downloader`：扩展，发 1.5.4。
- `xdown-website`：官网 xdown.goodexts.com，Nuxt 4 静态站，部署在 Cloudflare Pages。

## 1. 目标

1. **安装时打开官网，曝光一次。** 首次安装后自动打开官网的欢迎页，教用户怎么用，顺带带出教程和其他插件。
2. **卸载时打开反馈页，又曝光一次。** 卸载后浏览器打开官网的反馈页，收集卸载原因。
3. **反馈页能联系上用户。** 用户可以自愿留下联系方式，或授权我们在 x.com 私信沟通，把问题真正解决掉。
4. **全部用免费方案。** 在现有的 Cloudflare 上做，不另起服务器。

## 2. 参考：WAExport 的做法

源码位置：
- 扩展：`E:\WebstormProjects\wd-export-contact\src\background.js`
- 官网：`E:\WebstormProjects\waexport-website\app\pages\ext-wa-export-feedback.vue`

| 环节 | WAExport 的做法 | 我们怎么做 |
|---|---|---|
| 安装 | `onInstalled` 判断 `reason === 'install'` 时，`tabs.create` 打开引导页，带 `utm_trigger=install`、版本、语言 | 照搬，只在首次安装时打开 |
| 更新 | 不打开页面，只重新设置卸载地址 | 照搬 |
| 卸载地址 | `setUninstallURL`，参数带版本、语言、安装时间，**还带 WhatsApp 号码** | **不带任何用户标识**，只带版本、语言、安装日期，见第 6 节 |
| 反馈页布局 | 左栏是标题和两张自家产品推广卡片，右栏是表单 | 照搬：左栏推广我们的 X Blocker 和 X Article to PDF，再曝光一次 |
| 卸载原因 | 8 个单选，"无法工作""缺少功能""其他"三项必须填写详情 | 照搬，去掉"价格"（我们免费），见 4.1 |
| 选"隐私顾虑"时 | 弹出一个小标签："我们不收集任何数据" | 照搬，文案改成"扩展本身不收集任何数据" |
| 联系方式 | 没有 | **新增**，见 4.2 |
| 防刷 | 没有 | 同样不做人机验证：小插件流量低，验证码只会让用户放弃提交。只保留用户看不见的兜底，见 4.3 |
| 提交 | POST 到自家后端，再转发到钉钉群 | Pages Functions 接收，写入 D1 数据库，可选同时推送到 Telegram，见第 5 节 |
| 提交失败时 | 吞掉错误，照样显示"感谢反馈" | **不学**：失败要提示用户，并保留已填的内容 |
| 成功页 | 感谢语加"回到首页" | 感谢语、"重新安装"按钮和联系渠道 |
| 页面复用 | 带 `entry=feedback` 参数时切换成"一般反馈"模式，标题和文案都变 | 照搬：同一页面以后也能做扩展内的"意见反馈"入口 |
| 搜索引擎 | `noindex, follow` | 照搬，两个页面都不进 sitemap |

## 3. 欢迎页 `/welcome`

- 四种语言：英文在 `/welcome`，中文在 `/zh/welcome`，巴西葡语在 `/pt-br/welcome`，西语在 `/es/welcome`。
- 扩展按浏览器语言选对应地址。官网只有这 4 种语言，其余语言（日、韩、阿拉伯语等）都打开英文版。
- **定位：教会用户怎么用，而不是官网首页。** 不放营销大图，不放"立即安装"按钮（用户已经装了），每一步都配截图。
- 布局参考 WAExport 的引导页 `ext-wa-export-guide.vue`：每一步一行，文字和截图左右交替。手机上改成上下排列。
- 步骤和配图：

| 步骤 | 文案要点 | 配图 |
|---|---|---|
| 1. 把扩展固定到工具栏（标"很重要"） | 点右上角的拼图图标 → 找到 X Media Downloader → 点旁边的图钉；固定后图标会一直显示在工具栏 | 复用 WAExport 的 `guide_pin.gif`，见下方说明 |
| 2. 在帖子上点下载 | 打开 x.com 任意带视频、GIF 或图片的帖子，点"点赞""书签"旁边的下载图标 | 复用官网已有的 `promo-simple.webp` |
| 3. 选清晰度 | 右键下载图标，从 X 实际提供的版本里挑一个；默认清晰度在设置里改 | 复用 `promo-quality.webp` |
| 4. 批量下载整个主页 | 打开某个账号主页的"视频"标签页，点工具栏上的扩展图标，选"下载 @用户 的全部媒体" | 复用批量下载海报，或从海报工具重新渲染一张只含弹窗的图 |
| 5. 下载记录和设置 | 弹窗里"查看全部"进入下载历史，可搜索、重新下载、定位文件；文件夹和文件名在设置里改 | 选项页截图（用海报工具的同一套方式，加载真实页面配假数据，不暴露个人信息） |

- 页尾：两篇教程的链接、联系我们（WhatsApp、Telegram 群、邮箱）。
- **固定插件的动图要改过才能用。** WAExport 的 `guide_pin.gif`（480×274，104 帧）里显示的是 "Free Backup WhatsApp…" 和绿色的 WhatsApp 图标，直接用会让用户以为装错了插件。做法：
  - 逐帧把列表里的图标和名字、以及固定后工具栏上的图标，换成 X Media Downloader 的图标和名字。
  - 鼠标、弹出的扩展菜单和动画节奏都保持不变。
  - 每种语言用同一张图，因为 Chrome 菜单的语言跟着用户浏览器走，英文菜单最通用。
  - 替换后逐帧抽查，确认没有残留的 WhatsApp 字样或图标。
  - 这张图是公司自己的素材，可以复用。
- 标为 `noindex`，不进 sitemap，导航栏和页脚也不放链接。
- 现在安装后打开的是扩展自己的选项页，改成打开欢迎页。选项页从扩展图标里仍然进得去。

## 4. 卸载反馈页 `/uninstall`

四种语言的地址规则和欢迎页一样，同样 `noindex`、不进 sitemap。

### 4.1 卸载原因：必选，单选

| 值 | 中文文案 | 详情是否必填 |
|---|---|---|
| not_working | 用不了 / 有 bug | 必填，提示用户贴出帖子链接、说明发生了什么 |
| hard_to_use | 太复杂，不会用 | 选填 |
| missing_feature | 缺少我需要的功能 | 必填 |
| no_longer_needed | 不再需要了 / 只是临时用一下 | 选填 |
| switched_product | 换成了别的产品 | 选填，提示用户写是哪个产品 |
| privacy_concern | 隐私顾虑 | 选填；选中时显示"扩展本身不收集任何数据" |
| other | 其他原因 | 必填 |

详情文本框最多 2000 字。

### 4.2 联系方式：选填，给用户自由

- **联系渠道：** 下拉选择 WhatsApp、Telegram、微信或邮箱，再填号码或账号。
  - 不选渠道，就不用填。
  - 选了渠道，号码必填；邮箱渠道要校验格式。
  - 最多 100 字。
- **X 私信授权：** 一个复选框，**默认不勾选**。
  - 文案："允许通过 x.com 私信联系我，帮我解决问题"。
  - 勾选后才出现"你的 X 用户名"输入框，此时必填。
  - 用户名可以带或不带开头的 @，格式校验 `^@?[A-Za-z0-9_]{1,15}$`，存储时去掉 @。
  - 不勾选时，即使填过用户名也不保存。
- **隐私说明：** 放在联系方式下方。
  - 文案："以上都是选填，仅用于回复这次反馈，12 个月内删除"。
  - 附隐私政策链接。

### 4.3 其他

- **不加任何人机验证**，用户不会多一步操作。
- 只保留用户看不见的兜底：
  - 一个隐藏输入框（honeypot），正常用户看不到也不会填，机器人填了就直接丢弃。
  - 服务端限制请求大小，并逐字段校验。
  - 如果以后真被刷了，再加 Turnstile，届时只是加个开关。
- 提交时按钮置灰；失败时显示错误，保留已填内容；成功后换成感谢页。
- 如果用户同意了 cookie，就向 GA4 发一个 `uninstall_feedback` 事件。事件**只带原因这一项**，绝不带联系方式。

## 5. 后端：Cloudflare 免费方案

| 组件 | 作用 | 免费额度 |
|---|---|---|
| Pages Functions：`functions/api/uninstall-feedback.ts` | 接收表单提交，和静态站一起部署，同域名，不需要处理跨域 | 每天 10 万次请求 |
| D1：数据库 `goodexts-feedback` | 存反馈数据 | 5GB，每天 10 万次写入 |
| Telegram 机器人（可选） | 有人提交时推送到手机 | 免费 |

接口逻辑：
- 只接受 JSON 格式的请求，大小不超过 8KB。
- 服务端按和前端相同的规则把每个字段重新校验一遍。
- 隐藏输入框被填了，就假装成功、不入库。
- 用预编译语句（prepared statement）写入 D1。
- 记录 Cloudflare 自动给出的国家代码。**不存 IP，不存浏览器 UA。**
- 配置了 Telegram 时，在后台异步推送；推送失败不影响提交本身成功。

表结构，留一张表就够：

```sql
CREATE TABLE IF NOT EXISTS uninstall_feedback (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  ext TEXT,            -- 扩展标识 xmd；以后其他插件也写进这张表
  version TEXT, hl TEXT, installed TEXT, page_locale TEXT,
  reason TEXT NOT NULL, detail TEXT,
  contact_type TEXT, contact_value TEXT,
  x_dm_allowed INTEGER NOT NULL DEFAULT 0, x_handle TEXT,
  country TEXT
);
```

查看数据的方式：
- 在 Cloudflare 后台的 D1 控制台直接写 SQL。
- 或者用命令行 `npx wrangler d1 execute goodexts-feedback --remote --command "..."`。
- README 里会附几条常用 SQL：近 30 天各原因占比、留了联系方式的记录、到期清空联系方式。

## 7. 隐私与合规

- **商店声明不受影响。** 商店的"数据收集"声明仍是"不收集"：数据是用户在网站表单里自愿提交的，不是扩展收集的。
- **官网隐私政策四种语言都要补一节，写清楚：**
  - 收集什么：原因、详情，用户自愿填写的联系方式和 X 用户名，版本、语言、安装日期、国家。
  - 存在 Cloudflare D1。
  - 用途：只用于改进扩展和回复用户。
  - 联系方式 12 个月内删除，用户可以发邮件要求提前删除。
- **12 个月删除由你定时手动清理**，不做自动任务。README 里附一条清空到期联系方式的 SQL，原因统计保留。

## 8. 需要你操作或授权的部分

1. 在 Cloudflare 后台：
   - 创建 D1 数据库 `goodexts-feedback`，执行建表 SQL。
   - 在 xdown 的 Pages 项目里绑定这个数据库，变量名 `DB`，生产环境和预览环境都要绑。
2. Telegram 机器人（已确定要推送）。**进度（2026-10-05）：机器人 `@goodexts_feedback_2_bot` 已建好，chat_id 已拿到，测试消息已发送成功；剩下第 4 步（填进 Cloudflare）和第 5 步（换 token）。**
   1. 在 Telegram 里搜 @BotFather，发送 `/newbot`。名字随意，比如 `GoodExts Feedback`；用户名必须以 `bot` 结尾。创建完它会给你一串 token。
   2. 打开你的机器人点 Start，或发一句话。不做这一步，机器人不能主动给你发消息。想让团队一起看，就建一个群，把机器人拉进去，在群里发一句话。
   3. 浏览器打开 `https://api.telegram.org/bot<token>/getUpdates`，在返回内容里找 `"chat":{"id": ...}`，这个数字就是 chat_id（群的 id 是负数）。
   4. 在 xdown 的 Pages 项目 → Settings → Variables and Secrets 里添加两项：
      - `TG_BOT_TOKEN`：类型选 Encrypt（加密）。
      - `TG_CHAT_ID`：普通变量即可。
   5. token 相当于机器人的密码，不要发给我。
   6. 推送内容：插件名、原因、详情、版本、语言、国家、联系方式、X 用户名（仅在授权时）。

本地开发阶段用本地 D1，不碰线上资源，也不登录你的 Cloudflare 账号。
